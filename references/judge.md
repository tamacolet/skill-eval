# 訂正の判定と書き方

## 拾い方

成果物ややり方を変えさせた発言だけを訂正として拾う。

| 発言 | 扱い |
|---|---|
| 「〜にして」「〜は不要」「〜が分かりにくい」 | 訂正。複数あれば1件ずつに分ける |
| 最初の依頼文にある作り方の指定 | 訂正と同じ（毎回言わされているかもしれない） |
| AIのおすすめと違う選択肢を選んだ | 訂正 |
| 作業中の短い割り込み（「skillにも登録して」等） | 直前の発言とつなげて1件にする |
| 質問・状況確認・許可・作業の追加依頼 | 拾わない |
| 中継 | 本人の言葉と明記された部分だけ拾う。他は質問で確かめる |
| 貼り付けの中の文 | 本人が指して頼んだ時だけ拾い、範囲は必ず聞く |
| 自動応答 | 拾わない。範囲の根拠にもしない |

- 何に対する直しかを1行で言えない時は、`extract --max-chars 0` で前後を読む。
- 同じ訂正が別の会話にもあるかは `find --grep <語> --days 30` で数える。2つ以上の会話に出た訂正は「毎回」の強い証拠（範囲を言い切っていなければ、それでも聞く）。

## 照らし合わせ

対象skillは、その決まりを実際に作る係が読むファイルを持つskill。SKILL.md・references・検査を訂正の語で検索し、状態を付ける。

| 状態 | 次の手 |
|---|---|
| 未記載 | 範囲を決めて登録 |
| 記載あり・守られず | 文を足さない。原因を1つ選ぶ: 係へ渡る資料に無い→移す／見本が逆→見本を直す／機械で見られる→検査にする／資料の奥にある→入口の表へ上げる |
| 食い違い（skillが逆を言う） | どちらを残すか聞き、古い方を消す |
| この会話で登録済み | 登録文が本人の言葉より広くないか、条件が抜けていないかを見る。広ければ聞いて直す |
| skillの外（道具の不具合・データの誤り・その場の好み） | skillに書かない。不具合は直すか報告する |

メモリにだけある決まりは、skillへ移してメモリは索引の1行にする。

## 範囲

| 範囲 | 目印 | 例 |
|---|---|---|
| 毎回 | 本人が範囲まで言い切った／別の会話でも同じ訂正 | 「◯◯の動画は必ずコードを入れる skill登録」 |
| 条件つき | 題材・媒体・場面の名前が付く、「〜の時は」 | 「一括1円の機種がある回は〜」 |
| 今回だけ | 題材の事実、素材の都合、「今回は」「とりあえず」 | 「7:24あたりで別動画にすると言う」 |
| 不明 | どれとも言えない | 「タイルに2年返却か一括かを書いて」 |

- 今回の素材への直しに、毎回の決まりが隠れていることがある。「◯◯の画像が無い」は今回だけ、「画像の無い機種は作る」は決まりの候補。候補の方を聞く。
- 「skill登録」と言われても、範囲は別に見る。
- 数字・時刻・固有名は外して考える。外しても意味が残れば、その形で聞く。残らなければ今回だけ。
- AIが自分で決めた範囲は範囲ではない。
- 「不明」「条件つき」は必ず聞く。「今回だけ」は、本人の言葉に根拠がある時だけ聞かずに見送れる。

## 書き方

| 決めること | 基準 |
|---|---|
| 置き場所 | 作る係が毎回読む所。SKILL.md の末尾に足し続けない |
| 文の形 | `条件 → やること`。条件つきは条件を文の頭に書く |
| 注記 | 文末に `（YYYY-MM-DD ユーザー指示・<題材>）` |
| 見本 | 例・テンプレが訂正前のままなら一緒に直す（係は文より見本を真似る） |
| 検査 | 有無・字数・語・順番・数のように機械で見られるものは、対象skillの今ある検査へ足す。条件つきの決まりは検査も同じ条件で動かす |
| 消すもの | 訂正と逆の古い文・古い見本 |

## 確かめ

1. skillの大きさ検査: `python3 ~/.claude/skills/skill-creator/scripts/quick_validate.py <対象skillのフォルダ>`
2. 対象skillのテスト・検査
3. 足した検査が、直す前の成果物で止まり、直した後で通ること
4. 他のskill・メモリに逆の決まりが無いこと
5. 条件つきの決まりは、条件に当たらない題材で検査が止まらないこと
