# skill-eval

AIに頼んだ文章・資料・動画・コードを、何度も直して仕上げた。そんな**直しを、次から言わずに済むようにする** Claude Code 用の skill です。

会話の記録から直しを拾い出し、今ある skill に決まりとして書き足します。
作るものの種類は問いません。

## しくみ

```mermaid
flowchart TD
  A["会話の記録"] --> B["直しを<br>拾う"]
  B --> C["skillと<br>見比べる"]
  C --> D{"いつも<br>やる？"}
  D -->|"毎回"| E["skillに<br>書く"]
  D -->|"時々"| F["条件つきで<br>書く"]
  D -->|"今回だけ"| G["書かない"]
  D -->|"不明"| H["本人に<br>聞く"]
  H --> D
  E --> Z["次から<br>言わずに済む"]
  F --> Z
```

## なぜ聞くのか

直しをそのまま全部書き足すと、**今回だけの直しが、毎回の決まりになってしまいます**。

| 直しの指示 | 本来の範囲 | そのまま書くと |
|---|---|---|
| 「3枚目の図だけ色を変えて」 | 今回だけ | すべての図の色が変わる |
| 「表に単位を書いて」 | 金額の表だけ | 不要な表にも単位が付く |
| 「まとめは必ず入れて」 | 毎回 | 問題なし |

そこで、範囲がはっきりしない直しは、選択肢から選ぶ質問で確認します。

```text
「表に単位を書いて」は、いつやりますか？

  ○ 毎回
  ● 金額の表だけ
  ○ 今回だけ（登録しない）
```

AIが作業中に自分の判断で書いた決まりも、指示された内容より広くなっていないか見直します。

## 書き足し方

```mermaid
flowchart TD
  A["直し1件"] --> B{"skillに<br>もうある？"}
  B -->|"無い"| C["範囲を<br>確かめて<br>書く"]
  B -->|"あるのに<br>守られない"| D["文は<br>足さない"]
  B -->|"逆のことが<br>書いてある"| E["残す方を聞き<br>古い方を消す"]
  C --> F["検査に<br>できるなら<br>検査にする"]
  D --> G["検査にするか<br>置き場所を<br>直す"]
```

## 入れ方

```bash
npx skills add tamacolet/skill-eval
```

または:

```bash
git clone https://github.com/tamacolet/skill-eval.git ~/.claude/skills/skill-eval
```

必要なものは Claude Code と Node.js 20 以上だけです。ほかのツールや特定の置き場所は必要ありません。

## 使い方

何度か直して仕上げたあと、Claude Code に次のように頼みます。

- 「今回の直しを skill に反映して」
- 「同じ訂正を繰り返さなくていいようにして」
- 「skill に入れた決まりが広すぎないか見て」

会話の記録から発言だけを取り出すツールとしても使えます。

```bash
E=~/.claude/skills/skill-eval/scripts/extract-log.mjs   # 入れた場所に合わせる
node $E find --grep "<探す言葉>" --days 3        # 会話を探す
node $E extract <会話IDの先頭8字> --out log.md    # 人の発言を取り出す
```

## 中身

| ファイル | 役割 |
|---|---|
| `SKILL.md` | 全体の流れ・質問の形式・守るべき決まり |
| `references/judge.md` | 直しの拾い方・範囲の決め方・書き方・確認のしかた |
| `references/skipped.md` | 「今回だけ」と決めた直しの記録 |
| `scripts/extract-log.mjs` | 会話の記録から発言を取り出す |

## 自分の環境に合わせる

自分の環境独自の手順（報告の出し方、検査のコマンドなど）は `references/local.md` に書いておくと、最初に読み込まれます。無くても問題なく動きます。
